# Product Card AI Service

FastAPI-сервис для подготовки черновиков карточек товаров через LLM.

## Возможности

- `POST /generate` принимает JSON с названием, производителем, характеристиками и описанием.
- Модель формирует SEO-заголовок и описание, поисковые запросы и коммерческий блок.
- Характеристики копируются из входных данных кодом, без генерации моделью.
- Один системный промпт задаёт стиль и формат результата.
- Пустые характеристики отмечаются как `данных нет` и перечисляются в `missing_data`.
- Если модель нарушила ограничения длины SEO-полей, сервис просит её исправить ответ, максимум три попытки. Между запросами делает паузы 1 и 2 секунды; текст не обрезается.

### Входной формат

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5"
  },
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

`name` и `manufacturer` обязательны. `specs` и `description` можно не заполнять.

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Добавьте ключ в `LLM_API_KEY` файла `.env`, затем запустите:

```bash
uvicorn app:app --reload
```

Swagger UI: <http://127.0.0.1:8000/docs>

Провайдер задаётся переменными `LLM_BASE_URL` и `LLM_MODEL`. По умолчанию используются Mistral API и модель `mistral-small-latest`.

## Примеры

Примеры входных данных и образцы ответа для двух товаров находятся в папке [`examples`](examples/). Образцы показывают ожидаемый формат; формулировки фактического ответа модели могут отличаться.

В ответах поле `characteristics` формирует сервис напрямую из `specs`. Модель получает только название, производителя и описание; она не видит значения характеристик.

## Принятые решения и ограничения

- Один endpoint FastAPI; база данных, веб-интерфейс и деплой не требуются.
- Один системный промпт задаёт B2B-стиль и формат JSON; данные товара передаются отдельным сообщением.
- API-ключ хранится в `.env`; файл исключён из Git.
- Технические характеристики не передаются модели: сервис копирует их из `specs` в ответ.
- Код отмечает пустые поля, но не определяет характеристики, которые должны быть у конкретного типа товара, но не пришли во входе.
- Ответ модели нужно проверять перед публикацией. Сервис ограничивает длину полей, но не проверяет фактическую достоверность каждого утверждения.

Логи попыток генерации отображаются в терминале с Uvicorn. Если модель не соблюдает длину за три попытки, сервис возвращает ошибку с фактическим числом символов.

Возможные улучшения: шаблоны обязательных характеристик по категориям товаров, проверка фактических утверждений перед выдачей результата и сохранение результатов генерации.
